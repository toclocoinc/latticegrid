The charts module

modules/charts draws forty-two chart types from the grid's own data. It is optional and imports nothing from the grid (the grid is handed in) so the bundle carries the drawing and none of the grid, and a page that never charts never loads it.

import { createChart } from '@toclocoinc/lattice-grid/modules/charts';

const chart = createChart({
  grid,                       // the grid to read
  container: '#revenue',      // an element or a selector
  type: 'bar',
  x: 'region',                // the category column
  y: 'revenue',               // the measure column
});

A chart reads the grid's filtered rows. Filter, sort or edit the grid and every chart bound to it redraws on the next frame: there is nothing to subscribe to and nothing to keep in step. A chart of rows the user cannot see would be describing a different data set.

Over a paged pushdown source, a chart aggregates through the engine, not the loaded window (GEO-5). The grouped types — line, step, area, bar, horizontalBar, waterfall, combo, pareto, heatmap, radar, funnel, stream, marimekko — ask source.aggregate() whenever the grid's source declares the pushdown group capability and the grid holds fewer rows than match: x and series become the GROUP BY, the measures its aggregates, and the grid's filter and quick search apply, so a bar totals the whole hundred-thousand-row relation rather than the hundred rows fetched so far. spec.aggregate ('auto' by default) forces 'engine' or 'client'; a forced 'engine' the source cannot serve is refused by name, never silently swapped. While a request is in flight the chart keeps its last drawing rather than going blank, and a burst of filter changes aborts the superseded request and coalesces to the one query the grid ends up on. A chart is never a mixture of the two — if any one measure would be computed client-side, every measure is — and chart.provenance() reports which happened, per measure, in the same engine/client shape source.aggregate() itself reports; the accessible summary says so too.

A chart given data it cannot draw (a candlestick with three measures rather than four) says so on the chart rather than drawing nothing, because a chart that silently draws nothing is indistinguishable from one that is broken.

Hierarchical data. The part-to-whole types read nested input from the grid's own grouping, not from the spec: with grid.columns.group(['region', 'product']) in place, the tree is that grouping, one level per grouped column in that order, and x is not consulted; depth caps how many levels are read. On a flat grid, x is the single level. What each type draws of that tree: a pie or donut draws the top level; a sunburst draws every level as a ring, each segment its share of the segment inside it, and names a segment on any ring where the name fits, leaving it unnamed where it does not; a treemap nests: children inside their parent's tile, each branch with a header band naming it and padding round its children, to the depth the tree has. A child whose tile would be smaller than a line of text is not drawn and its parent's tile stands for it, so the levels drawn are the levels that can be read; a small group at the top level is always drawn, as a labelled tile with no children inside it. drill descends the tree on click, on either: clicking any tile or arc, at any depth, makes that node the root — a tile nested two levels down, or a segment on the outer ring, not only the top level — and the drill event carries the full path of labels from the root to it. ascend() comes back out a level at a time along the same path.

Bars of every kind — 100% stacks, lollipops, floating bars, pyramids and bullets

stack: 'percent' stacks a bar, horizontalBar, area or combo to 100%: every column is the full height and the axis reads 0% to 100%. mark: 'lollipop' is a mark on bar and horizontalBar rather than a type of its own, because it changes only how a value is drawn — the slot, the baseline, the sort and the axis are the bar's. A floatingBar (and horizontalFloatingBar) is a type, because it changes what is drawn: its measure is a y: [lowCol, highCol] pair and the axis must cover every span, on a number or a date axis. A populationPyramid mirrors two halves (y split by a series of two values, or two measures) about a central axis, with absolute axis labels. A bullet is the bullet cell renderer's picture across rows: ranges are the bands' upper edges, the actual a bar from the scale's minimum, the target column a perpendicular marker, so a KPI reads the same in a cell and in a chart. Each follows the grid's filter and selection, takes every scheme form, has the accessible table and keyboard stops, and follows the light and dark themes.

A rolling axis.x.window that has aged past its data shows the empty state, not a picture drawn off-plot. The window's domain ends at the wall clock (see window under the axis options below), so a feed that has gone quiet for longer than the window's span would otherwise have every mark fall outside the plot, with the axes and legend still drawn as if the chart were healthy. The chart shows its empty state instead and warns once per chart instance, naming the span and how old the newest reading is, so a dead feed reads as no data rather than as a chart that quietly stopped moving.

The x scale comes from the column's type, and nothing else (BACKLOG-0001344). A temporal type — date, datetime, timestamp or dateString — draws a time axis; a numeric type draws a linear axis whatever its distinct count; every other type draws bands, one per distinct value. A declared numeric or temporal column is therefore never demoted to a band, which it used to be below thirteen distinct values — silently turning off fit, band and everything else that needs a continuous x. Where the column's type is not what you want, pin the scale with axis: { x: { scale: 'band' | 'linear' | 'time' } }: 'band' is how a numeric code column (a quarter, a rating, a star count) asks for its bands back, and 'time' or 'linear' lifts a column the grid types as text onto a continuous axis. That last case is worth knowing about: a grid built with no rows infers text and does not revisit it when rows arrive, so a streamed date column binds bands where the same column beside a populated grid binds time. The chart warns once when it bands a column whose values all read as dates or as numbers, naming the column, its type and the option that overrules it. A band scale always draws: a line, area or step on one is drawn through the band centres, and its labels are thinned to the pitch the font can be read at rather than one per row (axis.x.every overrides the count).

A date or time x runs oldest to newest, whatever the grid is sorted by (BACKLOG-0001699). A chart whose x is a date, datetime, timestamp or dateString column (or Date values, or axis: { x: { scale: 'time' } }) orders its points by x ascending, so a grid sorted newest-first no longer draws its axis backwards. This covers line, area, step, bar, candlestick, the multi-measure types, and the fan and decomposition chart modules. A category x keeps following the grid's row order, which is the order you chose.

A candlestick or a bar bands its x by default, and sits on the values themselves when you ask it to (BACKLOG-0001481). These two are the marks with a width, and a width has to come from somewhere: a band scale supplies one, and a continuous axis has nothing to offer but the interval between the readings, which moves as the data moves. So both stay banded whatever their column's type until axis: { x: { scale: 'time' } } (or 'linear') says otherwise. On a continuous axis each candle or bar is drawn centred on its own x value, one sampling interval wide — the median gap between consecutive x values, so an overnight or weekend hole does not widen every mark, less the type's usual padding. axis.x.barWidth pins the width instead, in the axis's own units (milliseconds on a time axis) rather than in pixels, because a pixel width would cover a different span of time every time the domain moved.

Why it matters for a live pane. On a band scale the readings are spaced evenly whatever their values, so a rolling axis.x.window can only move the picture a whole slot at a time, when a period closes — which is what a trading terminal shows as a pane that repaints in place and never scrolls. On a continuous axis the domain ends at the wall clock, so between two candles every mark slides left by the same fraction of a slot and the pane pans smoothly. Two more things follow from placing a mark at its value: a candlestick price pane and a bar volume pane given the same x, scale and window line up column for column, because both put the same instant at the same pixel; and an interval with no reading leaves a gap rather than closing up, which is the honest picture of a halt, a holiday or a dropped message. The marks at each end of the domain are held inside the plot, so the oldest and newest are drawn as part-marks rather than painted over the axis gutter.

axis: { y: { position: 'right' } } puts the measure axis on the right instead (BACKLOG-0001477) — the layout an AG-style price pane uses. It moves the axis line, its ticks and labels, and the plot's gutter with them, on any non-horizontal cartesian type and on candlestick (a horizontal bar's y is its category axis and has no measure side to move). On a dual-axis chart, setting it on y swaps y2 to the opposite edge, since the two can never share one side.

A continuous x axis takes the domain you give it (BACKLOG-0001483). axis.x.min and axis.x.max fix the visible domain exactly, on a time or linear x as they always have on y and y2, for every cartesian type — line, area, step, scatter, combo, and bar or candlestick once axis.x.scale has put them on one. On a time axis both are epoch milliseconds. Readings outside the pinned domain are clipped by the plot, not dropped from the data, so the tooltip, the hit test and the accessible table still describe every row the chart was given; a pair that does not increase is refused with one warning rather than drawing the axis backwards. This is the same domain the reader's own brush: 'zoom' writes and the same one a zoom narrows inside, so a pinned domain is the zoom's maximum extent rather than a rival to it.

A replay pane brings its own clock. A rolling axis: { x: { window: { kind: 'time', span } } } ends at Date.now(), which is right for a live feed and wrong for a recording: every reading in a session captured yesterday is older than the window, so the chart correctly draws nothing and says so. Name the pane's clock with window: { kind: 'time', span, now: () => clockMs } — the same now the Window class takes — and the window rolls against it instead, including the “the newest value is N s old” check. It is read on every draw, so a replay that advances its clock and calls chart.update({ axis }) per tick scrolls exactly as a live feed does. A now that does not return epoch milliseconds falls back to the wall clock and warns once.

The margin a chart leaves for its labels is measured from the labels (BACKLOG-0001343). Where a chart names its rows down the left — a correlogram's columns, a horizontalBar's categories, a gantt's tasks, a forest's coefficients, a heatmap's rows — the gutter is the widest name it will draw, capped at two fifths of the chart. Past that cap a name is ellipsised and keeps the whole of itself as aria-label, so a screen reader announces the real name and the glyphs still stop inside the chart; no label is ever cut mid-glyph, and the gutter is re-measured whenever the chart is resized. Widening the chart therefore gives the names more room, which is the thing a fixed margin could not do. Where the left-hand gutter holds a measure axis the room is estimated from five digits instead, because the numbers on it are not known until after the plot has been laid out. margin: { left } is added to whatever the labels need rather than competing with it.

A rule on the column colours the bar (BACKLOG-0001451). A single-series bar or horizontalBar — no series key — takes each mark's fill from the y column's own conditional-formatting rules, the same styleFor a cell and a network link already answer to, and the legend names the rules that fired instead of the one, unnamed series. Without a rule on the column, or with series set, the bars keep the scheme exactly as before — a rule and a series both mean “colour by something”, and only one is read at a time.

A scheme can colour by name instead of by position (BACKLOG-0001453). scheme: { Operational: 'green', Degraded: 'amber', Offline: 'red' } keys on the category for a pie, donut or sunburst; on the series value for any cartesian type with a series column; on the measure's title (falling back to its column) for the measure-based types — a bar or combo given several measures, a radar or a candlestick — so { 'Committed revenue': '#1f4d5c' } colours that measure on a combo exactly as it does on a bar (BACKLOG-0001638); and on the x category for a single-series bar or horizontalBar — the same "no series" case the rule colour above reads, and a rule still outranks the map where both apply. A bare array — scheme: ['#1f4d5c', '#b4701a'] — is the shorthand for { series: [...] } and colours series in measure order on every type, exactly as explicit (BACKLOG-0001638). The point of the map is what an ordered array cannot do: a category a filter removes never shifts the colour of the ones that stay, because each name's colour comes from the map rather than from where it happens to sort. A name the map does not mention falls back to the ordered scheme by its position among the other unmapped names only. A map and an array palette are two ways of choosing the same thing and do not combine — given both, the map wins and the array is ignored, once, with a warning (chart:scheme:array-and-map).

legend: { values: true } writes the number beside the name (BACKLOG-0001453). Each entry gets its own total appended after a thin space — the category's for a pie or donut, the series' for a series legend — formatted by the measure column exactly as a cell in that column would be, so a legend reading "Operational 42" and a filtered grid never disagree about what 42 means.

A donut can carry a figure in its own hole (BACKLOG-0001453): centre: { value: 'total', label: 'sites' }. 'total' sums the slices actually drawn, so hiding a category from the legend moves the figure with the slices rather than leaving it stale; a number is a caller's own figure, formatted the same way; a string is written through unchanged, for a centre naming something a sum cannot. label is a second line beneath the value. Both are sized to the hole a donut cuts — never a pie's, which has none — and are shrunk together, proportionally, and truncated rather than drawn past its edge.

A gauge can be a needle dial over threshold bands (BACKLOG-0001637). bands shades the range behind the value, clipped to min/max and drawn in order; needle draws a pointer from the centre instead of the filled value arc; ticks places values round the arc; and centre: { label } names the reading’s caption. The figure itself is the measure, formatted by its own column — a suffix % column reads 68%, not 68. A value outside min/max is clamped on the arc while the tooltip keeps the real number. With none of the new keys the arc dial is unchanged.

Clicking a chart

A chart emits click, hover, leave, focus, draw, drill, brush and legend — there is no point:click, point:hover or series:toggle. The common use is filtering the grid from a mark, which makes the pair two views of one selection rather than a chart beside a table. The click and hover payload is flat — { label, category, column, value, series, rowKeys, native, preventDefault }, with no point wrapper — where column is the grid column the mark filters on and category the value to filter it to.

chart.on('click', ({ column, category }) => {
  grid.filters.set({ col: column, op: 'eq', value: category });
});

Simplest of all, set filterOnClick: true in the spec and the chart applies exactly that filter itself on the clicked mark. The click event still fires first, so a handler that calls preventDefault() on the payload takes the click over instead.

Chart a selected range

A user who drags out a block of cells — a text column and the numbers beside it — is asking a question a spreadsheet answers with one gesture: chart this. chartRange is that gesture. It reads the selected range, derives the chart from its shape, and returns the same live Chart createChart does, so nothing about it is a second kind of chart.

  • The leading text column becomes the categories, and the numeric columns beside it become the measures. One number is a bar chart; several are a grouped bar. A block of pure numbers charts against the row position.
  • Hidden and unreadable columns are never charted. The range is resolved against the columns the reader can actually see, so a chart never carries a value the grid itself would not show.
  • It is bound to the range's own rows, filtered as the grid is filtered — the band the rectangle covers, not the whole sheet.
  • The type is a sensible default you can change: chart.update({ type: 'line' }), or pass type up front.

The derivation is pure, so a menu can ask what a range would chart as — the type, the dimension, the measures — before anyone draws it. deriveRangeSpec answers that, and chartRange then draws exactly it. This block proves the shape rule on a real grid; drawing needs a container, shown below it.

Regression diagnostics

A regression is not finished when it has coefficients; it is finished when the residuals have been looked at. regressionPlots turns a fitted model — the one grid.statistics.regressionModel returns — into ready chart specs, so the diagnostic pictures are one call rather than a hand-assembled spec each. It reimplements no charting and no statistics: the fit line’s confidence band is the module’s own ribbon primitive fed by the model’s own interval, and the multicollinearity plot is the existing correlogram paired with the model’s VIF.

The presets that map onto grid columns are returned as drawable specs: the fit with its band, residuals-vs-fitted (over the fitPredicted and fitResidual shadow columns), a QQ plot of the residuals, the multicollinearity correlogram, and — over the fitStdResidual, fitLeverage and fitCooksD columns (BACKLOG-0000872) — residuals-vs-leverage, a bubble sized by Cook's distance. Scale-location (√|standardised residual| vs fitted) is drawn from explicit points computed off the model, since its y is a transform no column holds; the coefficient forest plot draws one row per coefficient — its estimate with a confidence whisker and a line at zero — through the explicit-bound error-bar primitive. A preset a given model cannot support (no multicollinearity for one predictor, no band for several) is returned as a null spec carrying a machine-readable reason rather than silently dropped.

Maps

A geomap takes an ISO code from one column and a value from another. Alpha-2, alpha-3 and numeric codes are all accepted, and continent codes draw a continent map without any outline data. Codes that match nothing are counted and reported on the chart rather than dropped, a map missing half its data looks exactly like a map of a world where half the data is zero. The full code tables are in CHART-CODES.md.

Real outlines: geometry packs

A pack is an optional module you import only if you draw that map. Real boundaries are tens to hundreds of kilobytes, so none of them are in the charts bundle and the grid still fetches nothing at runtime: you import the pack you want, exactly as you import an extension chart type, and hand it to shapes. Each pack is TopoJSON — quantised and delta-encoded, decoded by the chart — generated from the published source below by tools/build-geo-packs.mjs, and it carries its own provenance: the source URL, the version, the date it was retrieved, the licence, and the attribution line that licence requires.

Network diagrams — icon nodes, links coloured by their value

A network draws the grid's rows as a graph: source and target name the two endpoint columns and y carries the value on the link between them. Three things make it a picture of your network rather than a generic hairball, and each is a fact only you have.

Nodes you name. nodes: [{ id, label, icon, x, y }] gives a node a glyph from the grid's own icon registry — a built-in name, or one you registered — and a label drawn beneath it. A node that appears in the rows but not in nodes takes the chart's icon default (a plain disc when there is none) and its own id as its label. A node listed in nodes that appears in no row is still drawn: a device with no links is a fact worth seeing. The glyphs are SVG paths from the same registry the cells paint from, so they are sharp at any chart size and take the chart's theme colours. This still works over a grid with no DOM of its own: createHeadlessGrid({ icons: {…} }) registers into that grid's own registry, and the chart resolves a node's icon from it exactly as it would on a rendered grid — a name neither it nor the built-ins hold still warns once, by name, rather than silently drawing a disc.

Positions you choose. x and y are fractions of the plot, measured from its top-left. A node giving both is pinned there and takes no part in the force simulation; everything else is laid out around it by the same deterministic relaxation as before, so “core on top, regions below” needs no hand-placed SVG. Half a position is not a position: a node with only x is laid out. A fraction outside 0 to 1 clamps to the edge of the plot rather than drawing where nobody can see it. Pinning one node never reshuffles the others — the layout's seeding draws for every node, pinned or not, precisely so that it cannot.

Colours from the rules you already wrote. Each link's stroke comes from the value column's own conditional-formatting rules, through grid.formatting.styleFor(col, value) — the colour order is background, then backgroundColor, then color; a gradient (a data bar, an icon set) is not a colour and is not read. A link no rule matches keeps the chart's default link colour. There is no chart-level threshold option, deliberately: a second place to say “red above 80” is a second place for the chart and the cell to disagree. The legend lists the rules that actually fired, with their own labels and their own swatches; a rule that matched nothing is not advertised. Change a rule and the links recolour on the next frame without the layout re-running, so nothing moves.

Links are undirected, and parallel links stay parallel. There are no arrowheads, and A,B is the same pair as B,A — a cable has two ends and no direction. Several rows between the same pair are drawn as several lines, side by side, offset perpendicular to the pair by 4 px and symmetric about it, in row order, each with its own value and its own colour. They are not summed: three circuits between two sites are three readings, and one line carrying 120% would be a number nothing measured. The tooltip on any one line names both endpoints and that line's own value, and the pointer picks out the line you are actually over rather than the pair. Width follows the value unless linkWidth fixes it.

Linked like every other chart. The graph is drawn from the grid's filtered rows and follows filter and sort. With selection: true, clicking a link selects its row and clicking a node selects every row it is an end of; the grid's selection then lights those links and nodes and dims the rest. A click handler still fires first and can preventDefault().

A least-squares forecast on the trend overlay (trend: { method: 'linear', forecast: n }) no longer draws a bare dashed line: it shades the uncertainty band around the projection (BACKLOG-0000975). Polar charts — a Nightingale rose, a radial bar and a polar scatter

Three opt-in modules draw a measure as a distance from a centre and a category (or a time, or a bearing) as an angle. Each is imported after the base charts module, registers its type by name, and is paid for only by the page that imports it. Each follows the grid's filter, answers a hover with a tooltip, takes the keyboard (one tab stop, the arrows between marks) and carries the accessible data table every chart has, and its marks, axes and legend use the same colour tokens, so they read in the light and dark themes alike. A scheme given as a bare array or as a name map colours them like every other type. The options that are particular to them are set in one polar object on the spec; startAngle, endAngle, max, min, stack, size and series mean what they mean elsewhere.

Polar area / Nightingale rose (modules/chart-polararea, drawPolarArea; type: 'polarArea', with the aliases 'nightingale' and 'rose') gives every x category the same angle and draws the wedge's radius from y. Polar scatter (modules/chart-polarscatter, drawPolarScatter, bindPolarScatter; type: 'polarScatter') places each row by an angle from the x column and a radius from y, with an optional size column (the dot's area), a series column (colour by category, with a legend) or polar: { colour: 'column' } (a number is drawn from the scheme's ramp, anything else by category). What the angle column means is stated with polar.angle rather than guessed, because the same number is a bearing in one chart and an hour in another. Every form is measured clockwise from twelve o'clock plus startAngle:

  • 'degrees' — a numeric column of degrees; any value wraps into one turn, so 370 is 10.
  • 'category' — the distinct values, in the order they first appear, spread evenly round the circle, one spoke each.
  • 'hourOfDay' — a time column read as the time of day, midnight at the top; 06:30 is 6.5 / 24 of a turn.
  • 'dayOfWeek' — a time column read as its day of the week, Monday first, the time of day kept within its day.
  • 'month' — a time column read as its month, January first, the day of the month kept within it.

A time may be an epoch in milliseconds, a Date or a date string, and is read in the grid's timeZone when it has one and in UTC otherwise. Left unset the angle is 'degrees' for a numeric column, 'hourOfDay' for a datetime or timestamp column, 'dayOfWeek' for a date column and 'category' for anything else. A row whose value does not read as that angle (or whose radius is absent) is not drawn at an invented one: it is counted in chart.data().unplaced. The angular axis is labelled for the form chosen (degrees every 30, hours every three, the weekday and month names in the grid's locale, a label per category) and the radial axis in the radius column's format. angleOf(value, kind, { timeZone }) is the same reading, exported for a host that wants to place its own marks against the one convention.

Word cloud — words sized by how much there is of them

modules/chart-wordcloud registers wordCloud. It reads either a word column in x with a value in y (one word per distinct value, sized by the sum of y), or a free-text column in text, which it splits into words and counts — lower-cased (lowerCase), with the built-in English stop words removed (stopWords: true by default there; false or your own array also work), and words below minCount left out. A word's font size is the square root of its weight, mapped onto minSize–maxSize (12 and 48 pixels).

Words are placed on a seeded Archimedean spiral from the centre, biggest first, each at the first spot where it is inside the plot and clear of every word already placed, so no two word boxes overlap, and the same data and seed always draw the same picture. rotate takes 0, a list such as [0, 90], or 'random'. Colour comes from the scheme (a bare array or a { word: colour } map) or from a colour column.

A word that does not fit is never dropped silently. chart.provenance().dropped counts the words that were wanted and not drawn (droppedBy splits them into beyond maxWords and no room), and the same count is written under the picture and in the accessible table. Clicking a word filters the grid to the rows that contain it — whole words only, so cat does not match concatenate — or, with selection: true, selects them; filterOnClick: false turns the click off. A map over a paged relation asks the engine for its view, and caps what it draws (GEO-6)

Over a paged pushdown source, a map draws the rows in its view, not the grid's page. A markermap, bubblemap or choropleth beside a grid holding 200 rows of 35,000 draws the 35,000 — or as many as are in view — not the 200. When the grid holds fewer rows than match, the map asks the source itself: a count through source.aggregate(), then the rows through the adapter's own execute — the grid's filter and quick search applied, no range window, capped at spec.viewportCap rows (default 20,000) — and, once the reader has panned or zoomed, a condition for the box on screen: a withinBbox on a geometry column (pushed as ST_CoveredBy by a spatial duckdbAdapter), or a between pair on lon/lat. The fetched rows are the map's own: nothing is injected into the grid, which keeps its page. A pan or a zoom asks again, aborting the request it supersedes, and the map keeps drawing its last answer under the new view until the next one lands. spec.aggregate governs this exactly as it governs a grouped chart: 'auto' asks only when the grid holds a window, 'engine' asks whenever the source can and is refused by name when it cannot, 'client' never asks. A projection without an invertible pair of scales (equalEarth, robinson, the conics) cannot name its box, so the map asks for the whole filtered relation, still capped.

Past the cap, density rather than a random subset. When more rows than viewportCap fall inside the view, a marker or bubble map draws square density cells, each filled by its count through the chart's ramp with a ramp legend: over a paged source the engine counts them (GEO-2's spatial buckets, { col, bucket: 'grid', size }, so a geometry column), and over rows the browser already holds the chart counts the same cells itself — 35,000 opaque bubbles at world scale are a blob whichever side counted them. The cell size follows the box the map is about to draw — the view, else a box the grid's filters hold on the map's column, else the data's own extent — so that box's longer side is 24 to 47 cells across (a power of two of degrees; a box is never binned at the world's size once one is known), and zooming in until the view holds no more than the cap returns to the rows. When the box the map draws changes by more than 2× in either axis, narrower or wider, the map refits its projection to the new box before drawing, so a few streets' points spread across the plot rather than bunching in the middle of a city's frame: a box set on the map from outside (a withinBbox through grid.filters.set() with viewportFilter on), or, at the initial view, the extent of the rows the grid's filters now keep (which also refits when it moves off the frame). A smaller change, and every pan, keeps the frame and moves the map under it. “Reset view” returns to the fit of the data. A choropleth has no honest density form, and an engine map that cannot bin (a lon/lat map, or an adapter without the grid bucket) has none either: past the cap each is refused by name (chart:viewportCap:over:*) and draws none of its rows, with the reason under the map. chart.provenance().viewport reports the rows drawn, how many matched the view, the cap, whether it was binned and how many cells, why nothing was drawn, the box, and whether the engine or the browser counted; the accessible summary says which, for example “12,480 points in this view, fetched from the data engine”.

A globe — the built-in maps on an orthographic projection

projection: 'orthographic' (alias 'globe') draws a choropleth, markermap or bubblemap as the hemisphere that faces the viewer, rather than a flat map: it is an option on the existing types, not a new module. Features on the far side are not drawn and cannot be hit; a polygon that crosses the horizon is cut there and closed along it, so land runs right to the edge of the disc. rotate: [lon, lat] is the point at the centre of the disc (default [0, 0]); drag turns the globe, wheel, + and - zoom in on it, Shift+arrows turn it from the keyboard and 0 returns it to rotate. There is no inertia, so nothing moves after the pointer lets go and reduced-motion preferences have nothing to switch off. The sphere's outline is drawn unless sphere: false; graticule: true (or { step }) draws the meridians and parallels, clipped at the horizon like everything else.

fitTo: 'selection' turns the globe to the middle of the rows the grid selects each time the selection changes, and chart.fitToSelection() does it once; it returns false when there is nothing to turn to. With viewportFilter the visible hemisphere is the filter: one withinDistance condition on the geometry column, a quarter of the Earth's circumference from the centre of the disc, rewritten as the globe turns, so every other viewer of the grid shows exactly the rows on the visible side. A globe that places rows by lon/lat has no single column to write that condition on, says so once and writes nothing. A globe has no annotate rail, because it has no pair of longitude/latitude axes to anchor one in.

A hierarchy as a graph, as circles, or as a tree — forceTree, pack, tree

Three opt-in chart modules draw a hierarchy, each as its own import so a page pays only for the one it uses: modules/chart-forcetree registers forceTree, modules/chart-pack registers pack and modules/chart-tree registers tree. All three read the hierarchy the way every hierarchy chart reads it — from a parentId column (each row names its parent by that parent's id column, or by row key when no id is given), from a path column (Europe/France/Paris, split on pathSeparator, default /), or from the grid's own grouping. A row whose parent is empty, unknown or leads back to itself hangs off the root, so one bad row costs its place in the tree and never the drawing. y sizes the nodes (a branch is the sum of its leaves); with no y a row counts one. Colour is by depth, or by a column with colourBy, and scheme takes a bare array or a title map as on every chart. Every one follows the grid's filter, so a hidden row leaves the picture; with selection: true a click selects the rows at or beneath the node, and a selection made on the grid dims the nodes that hold none of it. The keyboard walks the nodes with the arrow keys and Enter does what a click does, every node is announced with its path, and the accessible data table lists every node as CEO › Engineering › Web.

forceTree is a force-directed graph whose only links are parent to child: the root is pinned at the centre and the rest settle around it under the network chart's force layout. It settles in a bounded number of ticks — iterations, 220 for the first layout and 90 when a fold or a drag resumes it — and then stops; nothing keeps simulating behind the chart. A click folds or opens a branch; a node can be dragged and stays where it is dropped. pack is circles inside circles: a leaf's area is proportional to its value, a branch is the circle that holds its children, siblings never overlap (padding sets the gap) and the packing is deterministic, so the same rows draw the same picture. A click on a branch — or on a leaf, which goes to the branch that holds it — zooms into it, and a click on the circle that fills the view zooms back out; names are written inside the circles they fit. tree is a tidy (Reingold–Tilford) node-link tree: orientation is 'top-down' (the default), 'left-right' or 'radial', linkShape is 'straight', 'elbow' (the default) or 'curved', and cluster: true draws a dendrogram with the leaves in one row at the deepest level. No two nodes at a level overlap, a click folds or opens a branch and the layout is recomputed, expandDepth starts the deeper branches closed, and labels: true writes each node's value after its name. A tree too big for the plot is drawn to fit and can be zoomed: the wheel and +/- zoom, a drag pans, 0 resets (panZoom: false leaves them to the page).

A fold, an unfold and a zoom are animated, unless the reader prefers reduced motion — then they jump — or animate: false.

A crosshair — a cursor that follows the pointer, and the same cursor on every chart in a group

cursor: true puts a vertical hairline on a line, step, area, rangeArea, bar, horizontalBar, waterfall, scatter, bubble, candlestick, ohlc or combo chart that follows the pointer and snaps to the nearest reading in the data, not the nearest pixel. A label at the axis end of the hairline words the x as the axis does (its axis.x.format, else the column's format.pattern and time zone, else the full-precision date or number), and the tooltip lists every series' value at that x — open, high, low and close on a candlestick. The object form changes any of it: y: true adds a horizontal hairline that follows the pointer with its own label in the measure axis's format (and the right axis's, on a dual-axis chart); snap: 'none' puts the hairline under the pointer and labels the value there; labels: false drops the labels; tooltip: 'single' lists only the series nearest the pointer and tooltip: false lists none.

Groups share the cursor by value, not by pixel. Charts that name the same cursor.group show the cursor together: hovering one at 14:05 puts a hairline at 14:05 on every other, wherever 14:05 falls in that chart's own plot, with the hairline and axis labels on every member, and the tooltip on one: the chart under the pointer, or the one cursor.set was called on, so the members' tooltips never stack on top of each other. cursor.groupTooltips: 'all' gives every member that has a reading at the shared x its own tooltip, at its own hairline and in its own host, as a group showed them in 1.86.0 (they overlap when the charts share a place); the default is 'pointer'. The option is read on each chart, so a follower that sets 'all' shows its tooltip even when the chart driving the group says 'pointer', and tooltip: false still shows none anywhere. Any other value warns once (chart:*:cursor:groupTooltips) and is treated as 'pointer'. A category axis matches the category by key; a time or number axis matches the value and, with snap: 'nearest', lands on that chart's nearest reading. A chart whose range does not cover the value shows nothing rather than pinning the cursor to its edge. The charts may be bound to different grids and have different ranges. Zoom is not shared unless asked: set cursor.zoom: true (and zoom: true) on each member and a zoom, pan or reset of one is applied to the others, reported there as a zoom event with reason: 'group'.

Keyboard and screen readers. While the chart has focus, ← and → (↑ and ↓ on a horizontalBar) move the cursor one reading, Home and End go to the first and last, and Esc removes it; the other pair of arrows still walks the marks. Every deliberate move (keyboard, set(), row hover) is read out through a polite live region as the shared tooltip's text — “Tue: one 11, two 110, three 1,001” — while a sweeping pointer is not, so a mouse user with a screen reader is not read a sentence per pixel.

A tooltip never outlives its chart. The hover tooltip is hosted on document.body (or the shadow root, or tooltipHost), outside the chart root. If the host removes the chart's container from the document without calling destroy(), an open tooltip is hidden and removed as soon as the chart root leaves the document; destroy() still removes it directly.

Drive it, and listen to it. chart.cursor.set(x) puts the cursor at a category, number or date (false when the chart cannot place it), chart.cursor.clear() takes it away and chart.cursor.get() says where it is. cursor:move carries x, label, values (each series' text and raw number) and a source of pointer, keyboard, api, row or group; cursor:leave says what took it away. cursor.rowHover: true moves the cursor to the x of the grid row the pointer is over (through the grid's cell:mouseover), and a mouse-out removes it. Drag a mark to edit the row behind it

editable: true lets a reader change the data by moving the chart. Drag a bar’s end, a line or area point, a scatter point, either end of a floating bar or the edge of a pie or donut slice, and the value is written back to the grid — through the same door a cell edit takes, not through a copy the chart keeps. While the mark is held the chart shows the value it would write, formatted by the measure’s column (a currency column reads £1,250); on release it issues the edit with grid.edit.setCells() and the gated 'user' origin. So everything that guards a cell guards the mark: the column’s validation, a beforeEdit handler’s veto, edit.enabled (a read-only column, a read-only row), the undo stack, change tracking and router write-back. The chart then redraws from the grid’s cell:changed, which is also what happens when the same edit is made in the table or undone with grid.edit.undo().

An edit the grid refuses springs the mark back to where the data has it and says why in a status line under the plot: the grid’s own validation message (“Must be at most 100.”), the reason a beforeEdit handler gave to preventDefault(reason) (“That change was not applied: frozen by finance”), or a plain “That change was not applied.” for a read-only cell. The chart raises edit when the grid accepted a write and editRejected (with reason and message) when it did not.

Pass an object to say more: axis is 'y' (the measure, the default), 'x' (a scatter or bubble point on a numeric x axis) or 'xy' (both, which writes two cells in one undo step); min and max limit what can be written; snap rounds a drag to a quantum (true rounds to step, a number rounds to that), where an unsnapped drag is continuous to about a pixel’s worth; step is the keyboard increment. A drag may run past the end of the axis — the tallest bar sits at the top of its plot — and the axis rescales after the edit. A pie or donut slice is dragged by its leading edge and writes the slice’s value so that the redrawn edge lies under the pointer: the slice takes its share from every other slice at once, since a pie’s angles are shares of the whole.

A mark that is several rows is not draggable. A bar that sums a category has no single cell to write, so its handle is drawn inert (dashed, aria-disabled) and an attempt is answered, by name, in the console (chart:editable:aggregated) and in the status line — never by quietly doing nothing. editable.distribute says how a new total is shared out: 'proportional' scales every row by one factor (equal shares when the total was zero) and 'first' puts the whole difference on the first row. It needs a measure reduced with sum or avg (another reduction is refused by name, chart:editable:distribute), writes the rows in one undo step, and keeps none of them if the grid refuses any one: a total shared across only some of its rows is not a thing anyone meant.

The keyboard and touch. Every handle is a focusable slider with one tab stop for the lot. On a vertical chart Up and Down change the value by step (Shift takes ten) and Left and Right move to the neighbouring mark; on a horizontal bar the two pairs swap; on an 'xy' scatter the arrows move along x and y and Page Up and Page Down move between marks. Enter commits through the same path as a drag, Escape puts the value back, and Home and End go to the first and last mark. A finger drags like a pointer: the handles turn off the browser’s own touch panning, and the grab area is larger for touch. A drag does not also count as a click, so it never filters or drills the chart.

What cannot be dragged, said by name. A stacked or percent chart has no single value at the end of a mark, small multiples and the other chart types have no handles, a floating bar on a time axis is edited in the grid, and a chart of more than 2,000 marks draws handles on the first 2,000 (chart:editable:type, chart:editable:axis, chart:editable:cap). The handles are not part of an export: toSVG() leaves them out.

Anywhere a chart takes a colour for a filled mark, it takes a fill object. A hierarchy as fitted Voronoi cells — voronoiTreemap

The opt-in module modules/chart-voronoi registers voronoiTreemap: a treemap whose cells are the regions of a weighted (power) Voronoi diagram instead of rectangles. The shape — a circle by default, or any convex polygon given as clip: [[x, y], …] in any units, y down, scaled to fit the plot (a non-convex outline is filled as its convex hull, and fewer than three usable points fall back to the circle) — is split into one cell per top-level branch, each branch's cell into one per child, down to the leaves. It reads the hierarchy as every hierarchy chart does: a parentId column, a path column or the grid's grouping, with y sizing the leaves (a row counts one with no y) and the grid's filter applied.

The areas are fitted, not approximated. Each level starts from seeded sites spread over its shape, relaxes them towards the centres of their cells (which keeps the cells round), and then fits the weights by damped Newton steps until every cell is within the tolerance of its target area; each level is fitted to a share of the tolerance, so that compounded down the tree every leaf is drawn within tolerance — 1% by default — of its value's share of the whole. iterations sets the relaxations per level (10 by default; more rounds the cells off further and never changes how closely the areas fit), and seed the starting sites: the same rows and seed draw the same picture to the last digit. The fitting runs on the main thread, once per change of the data: the layout is kept against a signature of the values and options, so a resize, a theme change or any other redraw only rescales it. Measured on the release machine, 500 leaves take about 300 ms flat and about 100 ms as 20 branches of 25 in Chrome (the first draw, fit included), and about 320 ms and 90 ms in Node; a hierarchy keeps each level small, which is what keeps it fast.

A leaf takes its top-level branch's colour, so the branches read as regions (colourBy colours by a column instead, and scheme takes a bare array or a title map); the border between two cells is drawn in the background colour and is thicker the higher up the tree they part, so the gap between two departments is wider than the gap between two teams, in either theme. A leaf is named at its centre when the whole name fits inside its cell. The tooltip names the cell with its path and its share, the arrow keys walk the cells and announce each with its path, the data table lists every cell as Engineering › Web, and with selection: true a click (or Enter) selects the rows at or beneath the cell while a selection made on the grid dims the cells that hold none of it. The drawing reports what the fitting reached as fit: the worst cell's error, whether every level met its tolerance, and the milliseconds it took.

Responsive rules — a chart that changes shape at its container’s breakpoints

A chart that reads well at 640 px is cluttered at 300: the legend eats the width, the axis titles crowd the plot, the ticks collide. responsive is a list of rules, each a size condition and the options to lay over the chart while it holds: { maxWidth?, minWidth?, maxHeight?, minHeight?, set }. The sizes are the chart’s own container, watched as it resizes, not the viewport — so a chart in a narrow dashboard panel or layout window on a wide screen takes the narrow rules. Bounds are inclusive pixels, a rule needs every bound it gives, rules apply in order and a later rule wins. set takes any chart option; plain objects (legend, axis) merge key by key and anything else replaces. title, subtitle and footnote are built once and do not respond.

When a rule starts or stops matching the chart redraws with the merged options, and with none matching the base options are back exactly: the rules are always laid over what you set, never over the previous result, so a chart resized a thousand times is the chart resized once. Options you change later with chart.update() become the new base and the rules re-apply on top. A rule that is already active holds for 4 px past its edge, so a container sitting on a boundary does not flicker. Each change raises responsive after the redraw, with the rules now active ({ active: [{ index, auto, ...bounds }], width, height }), and chart.responsive reads them at any time.

responsive: 'auto' is a ready-made set: below 400 px the legend moves to the bottom, axis titles are hidden and the value axes take three ticks; below 250 px the legend goes too. It never switches on what you turned off (legend: false and axis: false stay off), and an explicit list of tick values is kept. The built-ins are ordinary rules listed first, so they are overridable: responsive: ['auto', { maxWidth: 400, set: { legend: { position: 'top' } } }] is the defaults with your own rule on top, and your rule wins.

Animation — an entry that grows in, and updates that move rather than redraw

A chart plays its marks in when it first draws and plays every change in the grid from the old drawing to the new. animation is on by default: bars and columns grow from the baseline, lines and areas draw left to right, pie and donut slices sweep open, and points scale and fade in. When the rows change — a filter, a sort, a row update, live data — the marks interpolate from where they were to where they now belong, matched by identity (a series and a category, a slice’s label path), not by position: a bar that stays moves and grows rather than being redrawn, a bar whose category arrives grows in, a bar whose category leaves shrinks out, and the axis re-ticks smoothly, each tick label moving to where its number now sits. animation: false draws the final state at once.

// The defaults: a 400 ms ease-out entry and update.

// Slower, linear, and no entry; or no animation at all.
createChart({ grid, container: '#trend', type: 'line', x: 'month', y: 'sales',
  animation: { duration: 800, easing: 'linear', entry: false } });
createChart({ grid, container: '#static', type: 'pie', x: 'region', y: 'sales', animation: false });

The object form takes duration (milliseconds, default 400; 0 is no play), easing ('linear', 'ease-in', 'ease-out', 'ease-in-out' or a function of 0..1), entry and update (each true by default) and budget. A value the chart cannot read is named once in the console (chart:*:animation:invalid) and the default plays in its place.

The end state is the same document. A play writes the final drawing first, puts each mark back where it was, and plays it forward; at the end every attribute it touched is written back exactly as the unanimated draw wrote it, so an animated chart and the same chart with animation: false end identical, attribute for attribute. Everything that reads the chart’s data — the tooltip, the hit test, the crosshair, the drag handles, the accessible table, chart.data() — reads the final drawing from the moment the draw returns; only the paint is in between, so a crosshair or a handle never sits at a stale position. toSVG() and toPNG() always export the final picture, finishing a play in progress.

Who gets no movement. prefers-reduced-motion: reduce, an automated browser (navigator.webdriver, which Playwright, Puppeteer, Selenium and headless Chrome set, so an end-to-end test reads final geometry straight after a draw), a jsdom or happy-dom test DOM (which name themselves in the user agent), and a render with no window (Node, a server, the test DOM) all draw the final state at once. So does a resize or a zoom, which is the reader moving the view rather than the data changing. chart.provenance().animation says what the last draw did and why: { animated, reason, marks, budget }, where reason is 'entry', 'update', 'disabled', 'reduced-motion', 'automation', 'no-window', 'own-motion', 'budget' or 'view-change'.

Live data does not queue, and big charts do not stutter. A draw that lands mid-play retargets from where the marks are on screen — no jump back to either end — and there is only ever one play per chart, so a feed at ten updates a second shows marks heading for the latest data rather than working through a backlog. Above budget marks (default 2,000) a draw is written at its final state at once and provenance().animation.reason is 'budget': the per-frame cost of moving every mark grows with the number of marks, and the budget is set where a frame stays well inside its 16 ms in a real browser.

One engine for every type. Every chart in a window plays on one requestAnimationFrame loop, and every in-between value goes through one interpolation. The built-in types are animated by mark kind — a rect’s box, a circle’s centre and radius, a line’s ends, a slice’s angles, a path’s numbers when its commands match (a line that gains a point is drawn at its new shape at once rather than morphed through shapes the data never had), a label’s position. An extension type adopts it by drawing its marks through the toolkit’s Pool with a stable key (pool.next(tag, className, key)) or data-series/data-point: the base then animates it with no code of its own. A type that plays its own motion — the bar chart race, the motion chart, the hierarchy folds — declares animates: true in registerChartType and plays on the same loop and interpolation, handed to it as ctx.helpers.frameLoop and ctx.helpers.tween. Those types honour animation: false too: a fold jumps and a race steps whole frames.

Drawing on a chart — a tool rail anchored in the data

The declarative annotations above are written by whoever built the dashboard and state a standard the data is judged against. annotate is the other half: it gives whoever is reading the chart a tool rail to state an observation on it — this trend, this level, this retracement, this note. Set annotate: true for the whole rail on the left, or an object to narrow it: tools picks which buttons appear (always in rail order, so two charts never read differently), rail is left, top or none (the tools and the pointer behaviour without the strip, for a host driving them from its own toolbar), and readOnly paints what is in the state and refuses every change — including the rail, because a strip of buttons that do nothing is worse than no strip.

Eleven tools: select/move, trend line (two points), horizontal line and vertical line (one value, labelled with it), parallel channel (two parallel lines and a fill), Fibonacci retracement (0, 23.6, 38.2, 50, 61.8, 78.6 and 100 % between two points, each level labelled with its own value), arrow, text, callout (a label with a leader to a reading), note (a pin), and delete. Available on the cartesian types — line, step, area, rangeArea, bar, horizontalBar, waterfall, scatter, bubble — and on combo and candlestick; asking for it on any other type warns and draws no rail rather than silently doing nothing.

Every drawing is anchored in the chart’s own data coordinates, never in pixels. An anchor is { x, y } where x is a category, a number or a date exactly as the x scale reads one and y is a measure reading, and the pixels are recomputed from the live scales on every draw. So a line drawn across a spike stays across that spike when the container resizes, when a rolling window advances, when the grid is filtered and when the theme changes. On a category axis the pointer resolves to the nearest band — the category the reader was pointing at — and on a horizontal bar the projection follows the swapped axes, so the same drag anchors to the same readings either way round.

Everything drawn lives in chart.state() as plain JSON and comes back through chart.setState() as the same drawings; restoring is silent, because reloading a saved view is not an edit anybody made. Each change is reported as annotation:added, annotation:changed or annotation:removed with the item, subscribed through chart.on(…). An individual item may carry readOnly: true, which lets a reader select it and see what it is without being able to move, edit or delete it. Keyboard: the rail is one tab stop with the arrows, Home and End moving within it, every button carries its accessible name from the message catalogue, Escape cancels the tool in use and Delete removes the selection.

Zooming a chart — five controls, the wheel, and a rolling window

brush: 'zoom' lets a reader drag a range out of a chart. It then leaves them there: no controls, no wheel, no pan, and no way back but a full reset. zoom is the whole interaction instead. zoom: true is the defaults; the object form narrows them: axes is x (the default), y or xy; buttons is hover (the default), always or none; wheel and pan switch those two gestures off; step is how much of the visible span one press of a control is worth (0.25 by default, so zoom in shows three quarters of what was shown and a pan moves by a quarter of it); and min is the narrowest the view may go, as a share of the full extent.

Five buttons — zoom in, zoom out, pan left, pan right, reset — fade in at the bottom edge of the plot on hover and on keyboard focus. The wheel zooms about the pointer, so the reading under it stays under it; dragging a zoomed plot pans it; on a touch screen a two-finger pinch zooms about the point between the fingers (the plot takes touch-action: none while it can zoom, so the page does not take the pinch); + and - zoom while the chart itself is focused, 0 resets, and so does a double-click. A configured brush keeps the drag — brushing is an explicit opt-in and panning is the resting gesture — so adding zoom to a chart that already brushes takes nothing away. Available on the cartesian types — line, step, area, rangeArea, bar, horizontalBar, waterfall, scatter, bubble, candlestick, ohlc — on combo, and on heatmap, whose columns zoom like a bar chart’s categories (its rows are a band with no measure behind them, so axes other than x warns there); asking for it on any other type warns and adds no controls rather than silently doing nothing. A time or numeric x zooms a range of values; a category x — and a bar or candlestick over dates, which draws them in bands — zooms to a contiguous run of categories; axes: 'xy' on a scatter or bubble zooms both axes, and a horizontal bar pans its categories with a vertical drag, the way they run.

A zoom composes with a rolling axis.x.window: the window is the maximum extent and the zoom is a range inside it. A view sitting at the newest end keeps the newest reading at the right edge as rows arrive and the window advances — which is what somebody watching a live feed wants — and a view the reader has panned back from stays exactly where they left it rather than being dragged forward. On a category axis the zoom counts categories, because the gaps between two bands are not values; the range is then stated as two of the chart’s own categories.

The view lives in chart.state() beside the drawings, as plain JSON that survives JSON.stringify, and comes back through chart.setState() — silently, because reloading a saved view is not a zoom anybody performed. Every move is reported as zoom with the range now drawn and what moved it (button, wheel, key, pan, pinch, reset, api, group or filter), and chart.zoom.set(range) and chart.zoom.reset() drive the same view from a host’s own toolbar. Every control is a real button carrying its accessible name from the message catalogue, the strip is one tab stop with the arrows moving within it, and a control that cannot act — pan on an un-zoomed chart, zoom in at min — is disabled rather than silently dead.

The grid following the zoom — viewportFilter on a cartesian chart

A zoom on its own only changes the picture. viewportFilter — the same option a map uses to filter its grid to the box on screen — makes the grid follow the visible range: once a pan or zoom settles (debounce, 150 ms by default), the chart writes one condition to grid.filters, so the table, a KPI and every other chart over the same grid show exactly the rows inside the view. It needs zoom (without it the option warns, chart:*:viewportFilter:zoom, and writes nothing) and is off by default.

  • Time and numeric x: between the first and last reading in view, inclusive, written as the grid stores them. A view sitting at the newest end is written gte its first reading instead, so a live feed’s new rows still reach the grid. viewportFilter.column writes the range to another column than x.
  • Category x (and a bar, candlestick or heatmap over dates, drawn in bands): in the visible categories.
  • Scatter and bubble zoomed in y (axes: 'xy'), when each point is one row: a second between on the measure column. A y zoom anywhere else — a line’s y is a total over the rows at one x, and so is a scatter’s when rows share an x — filters by x alone and says so once (chart:*:viewportFilter:y).

One condition per axis, owned by the chart. Each is its own single-column branch of the filter tree, so the column’s filter menu shows it and its Clear removes it, and each carries meta: { owner: 'chart-view', chart, axis }. The next pan or zoom replaces it; zooming back out to everything, reset, viewportFilter: false and chart.destroy() remove it. The rule for a filter you set yourself: the chart only ever replaces or removes a condition carrying its own mark. A condition you put on the same column — from the menu, the tool panel or filters.set — stays exactly as you wrote it and is ANDed with the chart’s, so the grid shows the rows both admit; when the chart’s condition goes, yours is still there. (The column menu edits a column’s filter as a whole, so clearing or replacing the column there removes the chart’s condition too, which resets the chart’s zoom.)

Two-way, and undoable. The condition is a filter like any other: grid.history.undo() takes it off and redo() puts it back. Clear it in the grid — the menu, the tool panel, filters.clear(), an undo — and the chart resets its zoom; an undo or a redo that puts one of the chart’s conditions back moves the chart’s view to it. Both are reported as zoom with reason: 'filter', and carried to a cursor.group with cursor.zoom like any other zoom. Grouped charts keep zooming together; a chart over the same grid narrows because the grid did.

A price-and-volume pane — candles over volume on one x axis

A trading screen reads price candles with the volume traded in each period underneath, in one chart: one x axis, one window, one zoom, one tooltip. volume on a candlestick draws exactly that — a price pane and a volume pane in one svg — rather than two stacked charts that share an x and a window and have to be kept in step by hand. volume names the column holding each period’s traded volume, summed per period; volumePane.height is the volume pane’s share of the plot’s height, 0.25 by default.

Both panes are drawn on one x scale, so a candle and its volume bar share an x by construction, and the x axis is drawn once, under the volume pane. Everything that moves the x axis moves both panes together: a rolling axis.x.window, a pinned axis.x.min/max, the zoom’s buttons, wheel and pan, and chart.zoom.set(). Each volume bar takes its candle’s rise or fall colour — the scheme’s positive and negative — and the volume axis starts at zero on the same side as the price axis (axis.y.position). The tooltip, and the hover and click events, read both panes at the hovered period.

The price axis is still the chart’s y axis. A drawing is anchored in price, a y zoom narrows the price pane, and chart.state() holds the drawings and the zoom exactly as it does for a candlestick without volume. The volume column is bound as the fifth measure, after open, high, low and close, so it appears in chart.data() and in the accessible table, and a measurer’s volume figure sums it. volume on any other chart type, or naming a column the grid does not have, warns once and draws no pane. A candlestick without volume is drawn exactly as before.
