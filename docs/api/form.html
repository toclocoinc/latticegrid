The form module

modules/form is an opt-in form builder: named items laid out in nested rows and columns, in its own bundle that grows grid core by nothing. It is a sold Lattice feature. The main owner pain it removes is the same one the shell removes — asynchronous redraw: when createForm(el, config) returns, every item is already in the document and already measurable, so there is no awaitRedraw() and no deferred paint. A host that reads getItem(name).el on the very next line measures a real element in the same synchronous task.

import { createForm } from '@toclocoinc/lattice-grid/modules/form';

const form = createForm(document.querySelector('#form'), {
  rows: [
    { fieldset: 'Account', items: [
      { type: 'input', name: 'name', label: 'Name', value: 'Ada' },
      { type: 'number', name: 'age', label: 'Age', min: 0, max: 120 },
      { type: 'checkbox', name: 'active', label: 'Active' },
    ] },
    { cols: [
      { spacer: true },
      { type: 'button', name: 'save', label: 'Save' },
    ] },
  ],
});

form.getItem('name').setValue('Grace');  // a silent write, no event
form.getValue();                         // { name: 'Grace', age: null, active: false }
form.on('beforeChange', (e) => { if (e.name === 'age' && e.value > 120) e.preventDefault(); });
form.setDensity('comfortable');          // control heights follow the grid's row height
form.destroy();

Rows, columns and blocks. A form is a tree of rows and cols, each nesting the other to any depth, plus items to lay controls side by side. A rows block stacks its children vertically and stretches them to its width; a cols block lays its children side by side, sharing the width equally by default (flex: 1 1 0, min-width: 0 — a child’s own width, flex or css still wins, and a percentage width is a share of the row’s width after its gaps, so three 33.3% items sit on one line) and stacking them into one column once the container drops below config.colsBreakpoint (default 480px, via a container query — 0 or false turns stacking off, so the row never stacks at any width). A container is the default block shape (a flex box along its axis); a fieldset is a native <fieldset>/<legend> with its children in a body below; a spacer is flexible space and a separator a rule — or, given a label (a literal such as 'or', or a key resolved through config.messages), a muted label centred between two rules (“—— or ——”), the label also its accessible name — both plain blocks. A text item renders a read-only display carrying its value — a label/value pair, not an editable control — and the basic controls are input (subtype text, email, password or url), number (step/min/max), textarea, checkbox, button, rating (a row of icons, whole or half steps, click or arrow), stage (a pipeline of chevron steps), chips (a row of pill buttons for one or several options) and combo (a searchable combobox, described below).

One item, one handle. Every item is a wrapper holding an optional <label> (associated to its control by for/id), the control, and an optional help line. Per item: name, label, labelPosition (top/left), labelWidth, width, placeholder, helpMessage, hidden, disabled, readOnly and value. getItem(name) returns the handle — { el, name, getValue, setValue, show, hide, enable, disable, focus, blur, isVisible } — or undefined for an unknown name, and forEach(fn) hands every handle to fn in document order. setValue(values) writes values silently by name (unknown keys are ignored), getValue() snapshots every named value-holding item as { name: value } (a button holds no value and is not included), and clear() resets each user-editable item to its empty value — '' for text, null for a number, a stage or a single chips, [] for a multi chips, false for a checkbox, 0 for a rating — without firing an event.

Events. A field fires input as the user types (the value is live, not yet committed) and change once the edit commits; a checkbox fires change on toggle; a button fires click. Every interactive item fires focus and blur, and an otp fires complete once every box is filled. A change is gated by a cancellable beforeChange — a handler calls event.preventDefault(reason?) or returns false (or a Promise of either) to refuse the commit, which then reverts the control to its last committed value — and the emitted events are subscribed with form.on(name, fn) (or '*' for every past-tense event) and detached with form.off(name, fn).

Validation. An item declares required (an empty value fails), a validation rule — a built-in name (email, number, integer, url), a whole-value RegExp, or a function (value, item) => boolean | string | void that returns true/undefined for pass, false for a fail, or a string that is the failure message — and the message options errorMessage, successMessage and preMessage. form.validate() checks every rule-bearing item and returns true/false, marking each invalid item with aria-invalid and an associated message (and each pass with its successMessage); item.validate() checks one item. A validationMode of change re-checks an item once its edit commits, blur re-checks it as it loses focus, and submit (the default) checks it only on validate(). The default rule messages live in the module's catalogue — overridable through config.messages — and a validated event reports every failure as { name, rule, message }. The control registry exposes a per-control validate(el, item, value) hook that later controls (file, combo, custom) plug into.

Density. A density level — compact, standard (default) or comfortable — drives every control's height, padding, label gap and fieldset spacing from the grid's own --lattice-* tokens (a control stands one --lattice-row-height tall, so a form beside a grid follows that grid's density), each with a literal fallback so a form on a bare page still draws. form.setDensity(level) changes it live with one attribute write and no re-render, and an unknown level is ignored. The module imports no grid and no core source, ships in its own bundle and UMD global, and destroy() empties the element, removes only what the module added, restores the host's own inline style, and drops every item record, listener and handler.

Spacing and label gap. config.spacing sets the vertical gap between stacked items — a px number or a CSS length — and config.labelGap the gap between an item's label and its field; both default from the density scale, so leaving them unset changes nothing. They are the theme tokens --lattice-form-item-gap and --lattice-form-label-gap, so a CSS theme can set the default a form without an explicit spacing falls back to, and a rows container or fieldset that sets its own spacing overrides it for its own items only. form.setSpacing(value) applies the gap live with one property write and no re-render (null clears the override). Horizontal cols containers keep their own gap, and help/validation lines sit inside the item wrapper, so an item showing a validation message keeps the same gap to the next item as one without.

Disabled and read-only, defined once. Both states are one contract applied identically to every control. disabled leaves the tab order (unless focusableWhenDisabled), shows no hover or active response, sets cursor: not-allowed, carries aria-disabled (or the native disabled attribute), is excluded from validate(), and is styled from the --lattice-disabled-foreground/--lattice-disabled-background/--lattice-disabled-border tokens with text at or above 3:1. readOnly stays focusable and in the tab order, keeps its value readable, selectable and copied, refuses every change path before it happens — typing, click, paste, drop, wheel and the keyboard do nothing, pop-ups open view-only or not at all, and a checkbox, radio, toggle, radiogroup or checkboxgroup guards pointerdown/click/Space/Enter so the value never flickers — carries aria-readonly, is still validated and still appears in getValue()/submit, and is styled from the --lattice-readonly-foreground/--lattice-readonly-background/--lattice-readonly-border tokens (subtle fill, cursor: default, the lock icon). Both are set per item (disabled, readOnly, readOnlyWhen) and form-wide with form.setDisabled(bool) and form.setReadOnly(bool).

Data binding. config.bind binds the form to a record instead of a static config. bind: { grid, rowKey } binds a grid row: when no layout is declared, one item per column is generated from the grid's own columns — their titles, types and editors — so a boolean column becomes a checkbox and a number column a number; the form follows the grid's density by default; save() writes the dirty items once through the grid's edit path (permissions, read-only, parse, validation and the beforeEdit gate honoured); and revert() restores the bound values. External edits to the row update a clean item in place and leave a dirty one alone, flagging it with isConflicted(). bind: { router, route, key, onSave? } follows a data-router record with the same update-unless-dirty rule: the form reads the record eagerly through router.get(route, key) — so a form created after the ingest still fills at once, whatever the order — then subscribes to the route's keyed diffs, and destroy() unsubscribes. save() writes the dirty items back through router.apply, then calls bind.onSave(changes, record) when the host gave one (may be async; a rejection reverts the router record and leaves the form dirty). A form group takes the same bind once: every member fills with its own fields off the record, and group.save() writes one router update with all the members' dirty fields, calling onSave once. A plain object of values initialises the form and is written back by save(). isDirty(name?) reports an unsaved user edit on one item or the whole form, and editing is the only thing that marks an item dirty — setValue(), revert() and bound-record updates are silent. The binding is duck-typed against the grid's public API, so the module still imports no grid and no core source.

Custom controls. registerControl(type, definition) makes a control type a first-class item: the definition's create(el, item, api) builds the control's DOM into el, getValue(el)/setValue(el, value) round-trip the value through getValue()/setValue(), and an optional validate(value, item, el) refuses a bad commit (return true to accept, false or a message to refuse, a Promise is awaited). The registered control gets the same wrapper, label, item API, events and density as a built-in, its api.onChange()/api.onInput() commit and report through the same path a native edit takes, and a later registration for the same type replaces the earlier one.

Declarative rules. An item's visibleWhen, readOnlyWhen or requiredWhen is a rule re-evaluated on every committed change: a constant, a function of the whole { name: value } snapshot, or a condition on one named item's value with equals, in, empty or fn. A visibleWhen that is false hides the item, a readOnlyWhen that is true makes its control read-only, and a requiredWhen that is true marks it required — its commit path then refuses an empty value. A rule composes on the item's own hidden/readOnly baseline, so it never fights the item API's hide()/show()/enable()/disable().

Wizards. A steps array turns the form into a wizard: each { id, label, rows } step is one body, only the active one visible, under a step indicator whose stepOrientation is horizontal (default) or vertical. form.next(), form.goToStep(index) to a later step, and a click on a later indicator step all validate the current step's items first — exactly as form.validate() does, so a refused move shows the same errors, fires the validated event and moves focus to the first invalid item, resolving false and staying put. form.back(), goToStep(index) to an earlier step and an earlier indicator step go back without validating; the indicator marks each step pending, active, complete or in error, and never disagrees with the form. On the last step next() reads "Finish" and validates in place, resolving false while it is invalid. Set validateSteps: false to opt out — the integrator then runs validate() itself, and forward navigation is unchecked.

Files and rich text. A file item is an uploader field: drop, paste or pick, with accept (extensions or MIME patterns), maxSize and maxFiles enforced at admission, and a host upload(file, { onProgress, signal }) callback that does the actual upload. The file list shows per-file progress and status with retry and remove, and the value is the accepted file entries — a rejected file stays visible with a message but never enters the value. A richtext item is a sanitised HTML editor: toolbar presets (basic/html/rich or an item-name array) over bold, italic, underline, strikethrough, colour, case, paragraph styles, lists, alignment, links, images, source view and undo/redo, with keyboard shortcuts and paste cleanup. Its whitelist sanitiser is the security boundary, shared with the grid's rich-text editor as one implementation: scripts, event handlers, srcdoc, id/name clobbering and javascript:/vbscript:/data: URLs never survive pasting, dropping or setValue, and every _blank link carries rel="noopener noreferrer". Both honour density, theme tokens, readOnly/disabled and the item API, and clear to [] (file) or '' (richtext). The same rich-text editor is available as a grid pop-up editor for long text with edit: { editor: 'richtext' }.

Passwords and one-time codes. A password input carries a reveal button inside the field: an eye that toggles the input between the native password and text types, keyboard-operable like any button, carrying aria-pressed and a name from the catalogue (“Show password”/“Hide password”). It returns to hidden when focus leaves the field and when the form validates or submits, and reveal: false renders a bare password input with no button — the value, events and validation are unchanged. An otp item is a one-time-code entry of single-character boxes: length (default 6) sets how many, mode (numeric default or alphanumeric) drives each box’s inputmode/pattern and the characters it admits, the first box advertises autocomplete="one-time-code", and mask hides each glyph behind the password disc. Typing advances, Backspace steps back and clears, the arrow keys move, and pasting fills every box (spaces and dashes stripped). getValue() returns the joined string, setValue() fills the boxes, and a complete event fires once every box is filled. Screen readers hear one labelled group, each box announced as “Digit n of length”.

Buttons and button rows. A button item is an acting control, not a value: it takes an icon (a name from the grid’s icon set, an image URL or data: URI, or an element) with iconPosition (start default / end), sitting a density-scaled gap (about 0.5em) from the text and vertically centred with it, a variant (primary, secondary default, tonal, outline, text or danger — theme-token colours, light and dark), fullWidth to span the form (inside a cols row it fills its own column, so two full-width buttons keep sharing the row), a size (sm/md/lg), a textTransform (none default / uppercase) and a buttonType (button, submit or reset). A submit button runs form.validate() first and only then fires a submit event on the form’s element with the values in event.detail.values when valid; a reset button calls form.clear(). loading: true (or item.setLoading(bool)) swaps the icon for a spinner, keeps the width, sets aria-busy and makes the button ignore clicks; a href turns it into a link styled as a button. An icon with no label is icon-only: it requires ariaLabel and renders square. A { type: 'buttons', align, items } row lays a group of buttons out along the width with align start (default), end, center, stretch or space-between, and each child takes the same options as a button item.

A button is an action item, and its states are named tokens. Because a button acts rather than holds a value, the view draws no field <label>, required asterisk, help line or hint line for it — its label is its own text, shown once — and in a labelPosition: 'left' form it lines up with the fields’ input column (unless fullWidth spans the row). Every variant defines the same state matrix in light and dark, each state’s colours read from an overridable --lattice-button-<variant>-<state> token: rest; hover (one step toward the foreground — a shade in light, a tint in dark); active (a deeper step); focus-visible (a 2px accent ring with a 2px offset, never removed); disabled (muted text, border and fill with text at or above 3:1 against its fill, cursor: not-allowed, no hover or pressed change, aria-disabled, and still in the tab order only when focusableWhenDisabled: true keeps it focusable instead of natively disabled); loading (the spinner from loading); and toggled (a distinct pressed look). toggle: true makes the button two-state: it flips aria-pressed and fires change with the new boolean (starting pressed when value is true). The combo control

The same module also ships createCombo(el, config), the standalone form of the form's type: 'combo' item: a searchable combobox with dynamic server values, dependent lists, multi-select and multi-line options. It is a load-driven paging list — the search is debounced, a newer load aborts the older one, pages load on scroll and are cached, and reload() drops the cache — or a static options list when there is no server. Options are a bare value or { value, label, description, icon, avatar, color, dot, disabled }; a description adds a second line, an icon is a glyph name from the grid's icon set drawn as the real SVG (or a DOM node) and an avatar is an image URL or initials, each drawn round on the left of the list rows, the multi-select chips and the single-select shown value, in a virtualised list of variable-height rows; color tints the initials avatar and the icon (an SVG takes it as its fill or stroke, an element as its colour), and dot draws a small filled circle in that colour instead of any icon or avatar, with no letter; a disabled option shows but refuses a click. A multiple combo keeps its value as an array in selection order and draws chips that wrap, cap at maxHeight and scroll, with a +N summary and a selectAll action over the loaded set. chipPlacement moves those chips out of the control — 'above' or 'below' puts them in their own wrapping row beside the field, so the input stays a single clean search line and the list still opens directly under it. resolveLabels(values) supplies labels for a preselected value outside the first page, newOptions turns the box into free entry (with a create row while typing), optionTemplate replaces the row renderer and selectedTemplate the chips and shown value — either may return a DOM node or an HTML string, which is sanitised before insertion — and a form item's dependsOn clears and reloads it when a named parent item changes. The list opens in the same shared top-level layer the select and the date picker use, positioned against the field so a clipping or fixed-height ancestor never cuts it off (BACKLOG-0002291).

Pressing the FAB (or hovering it with openOnHover) opens items — each { id, icon, text, disabled, render }, icon-only, text-only or both — as a linear strip whose direction is up, down, left, right or auto (picked from position), or as a radial fan with mode: 'radial' whose radial startAngle/endAngle/offset default from position. modal: true paints a backdrop that swallows page clicks; a click on an item fires itemClick once and closes, outside/Escape closes with focus back on the FAB, and the keyboard model moves across items with the arrows (skipping disabled ones) and activates with Enter or Space. The FAB swaps openIcon/closeIcon, may carry a text label, and takes one of seven theme variants; dark mode and RTL mirroring are built in. The menu is a role="menu" of role="menuitem"s; the FAB is a role="button" with aria-expanded and aria-controls.

Form groups

createFormGroup(forms?, options?) joins several forms — for example one mounted per cell of a shell layout — into one logical form that never renders anything. getValue() merges every member’s values in add order; setValue(values) routes each key to the member that owns that field (the first owner wins when two forms declare the same name, unknown keys are ignored); getItem(name) reaches the owning member’s item handle; validate() validates every member and returns one boolean, focusing the first invalid field in add order and scrolling it into view; and setReadOnly(bool)/setDisabled(bool)/clear()/reset()/isDirty() apply across the members. A member’s change or validated event re-emits on the group as { form, name, value } or { form, valid }, naming the member it came from, and on/off subscribe and detach. A member that is destroyed leaves the group by itself, and group.destroy() detaches the group’s listeners without destroying the forms. options.transform = { get, set } lets a host join the merged values on read and split them back on write.

A member’s visibleWhen, readOnlyWhen and requiredWhen conditions may watch a field of another member. A condition { name, equals | in | empty | fn } whose name the form does not own resolves against the member that owns that field, so a details form can show a field only while the header form’s plan is enterprise. A condition may instead pin the member by its group.add(form, { id }) id — { form: 'header', name: 'status', equals: 'open' } — and an unknown id reads empty with a once-per-id warning. Rules re-evaluate when the owning member’s value commits, on group.setValue(), and when members join or leave; a rule whose source member leaves the group reads an empty value, and a form outside any group behaves exactly as before.

Three forms, one per cell of a shell, joined as one logical form: the merged value is read, a key is routed to its owner, a field in the third form is reached, the whole group validates, a cross-form visibleWhen shows a details field once the header’s plan turns enterprise, and a single Save button reads group.getValue() — run over the in-tree DOM test double, with the focus and aria states asserted against real Chrome in test/form-group-2207-browser.test.js.

const { root, document: doc } = createTestDom();
const shell = createShell(root, { rows: [
  { id: 'header' }, { id: 'details' }, { id: 'notes' },
] });
const header = createForm(shell.getCell('header').el, { rows: [
  { type: 'input', name: 'name', label: 'Name', value: 'Ada' },
  { type: 'input', name: 'plan', label: 'Plan', value: 'team' },
] });

  { type: 'input', name: 'email', label: 'Email', value: 'ada@example.com' },
  { type: 'input', name: 'coupon', label: 'Coupon', visibleWhen: { name: 'plan', equals: 'enterprise' } },
] });

  { type: 'textarea', name: 'notes', label: 'Notes', value: 'hello' },
] });

save.destroy();
shell.destroy();
