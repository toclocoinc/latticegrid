The data view module

modules/dataview is the list view's card-grid sibling: items laid out as cards that wrap into rows, each card drawn by your own template. A person selects cards (single and multi), moves through them with the arrow keys in two dimensions, and drags a card to a new position; a drop indicator shows where it lands. It builds on nothing but the DOM — there is no grid factory to inject — and draws only the rows of cards in (or just beyond) the viewport, so 5,000 items cost the same as a screenful.

import { createDataView } from '@toclocoinc/lattice-grid/modules/dataview';

const view = createDataView(document.querySelector('#cards'), {   // give the host a height
  data: [{ id: 1, name: 'Ada' }, { id: 2, name: 'Grace' }],
  template: (item) => `<h4>${item.name}</h4>`,
  itemWidth: 180, itemHeight: 96, gap: 12,    // or columns: 4 to fill the width
  selection: 'multi',
  dragMode: 'both',
});

Layout. Cards are itemWidth by itemHeight (default 200 by 120) with gap (default 8) between them, and as many as fit go on a row. itemHeight may be a percentage string such as '50%': each card is then that share of the view's own height, recomputed when the view resizes. Set columns: n instead and exactly n cards share the width, so the row is always full; itemWidth is then ignored. The view resizes with its host. Give the host element a height — the view fills it and scrolls inside it.

The list view's API, reused. view.data, view.selection and the event names are the list view's, and live in one shared file both modules import, so serialize(), filter(), sort() and the rest mean the same thing on both and always read back what is on screen. A returned template string goes through the same sanitiser the grid applies to template output; a returned element is used as it is.

Keyboard and pointer. A click selects a card; the platform modifier (Cmd on macOS, Ctrl elsewhere) toggles one into a 'multi' selection and Shift extends a range. One card is in the tab order; the arrow keys move between cards in two dimensions (Left and Right wrap across rows, Up and Down keep the column), Home and End go to the ends of a row (with the platform modifier, of the whole set), PageUp and PageDown move a screenful, Space toggles, Enter activates (itemDoubleClick) and Shift with an arrow extends the selection. In 'single' mode the selection follows the focus.

Item events and keys. itemContextMenu and itemMouseOver carry { id, item, event } (the shape the tree and list view emit) for a right-click on a card and for the pointer entering one; call event.preventDefault() to suppress the browser's menu. afterAdd { id, item } and afterRemove { id } fire on every data change, whether made through view.data or a drop. An item with no value in its key field gets a generated key when it is added, so it renders with a real data-key, selects, takes focus and drags like any other, and getItem() and serialize() carry that id.

Drag and drop. dragMode is the list view's: 'source' lets a card be picked up (reordering within the view, or sending it to another), 'target' receives, 'both' does either and false (the default) neither; dragCopy: true leaves the source card behind. A card dropped before the card whose left half the pointer is in lands there; afterDrop reports the new order and serialize() already matches the screen. A drag between two data views, or to and from a listview list, goes through the target's single beforeDrop: return false (or a Promise of it) and both sides are left exactly as they were. A reorder within one view is refused, with the reason announced, while a sort or filter is active, because the drop position would have no single meaning in the stored order. A dragCopy drop gives the copy a fresh identity rather than the source's — copyId(item)'s return when given, otherwise the source id with a -copy/-copy2/... suffix counted up until it is not already used in the target — so dropping the same card twice lands two items, and afterDrop reports that new id. A cancellable beforeDrag fires with {id, item} before a press on a card is armed as a drag: return false or call preventDefault() to stop that card dragging (a palette heading or a blank card, say). A press-and-drag that starts on a natively draggable element inside a card — an <img>, say — moves the item rather than letting the browser's own image drag swallow it.

Accessibility. The view is an ARIA grid of rows of gridcell cards with aria-rowcount, aria-colcount, aria-rowindex and aria-colindex, and aria-selected when selection is on. With no items it shows emptyText (default “No items”).

Layout, the data API and selection, executed

Cards per row from a width and from a column count, five items seeded, an insert, a patch, a sort, a filter that hides without losing anything, selection, and the redrawn cards in the same order as serialize() — run headless on every build with the suite's own DOM test double.

const { createTestDom } = await import('../packages/dom/src/renderer/testdom.js');
const { createDataView } = await import('../packages/modules/dataview/index.js');
const { computeColumns } = await import('../packages/modules/dataview/layout.js');

const fit = computeColumns({ width: 640, itemWidth: 100, gap: 10 }).columns;   // 5 cards of 100 and 4 gaps of 10 = 540
const filled = computeColumns({ width: 640, columns: 4, gap: 10 }).cardWidth;   // (640 - 3 * 10) / 4

const seen = [];
const host = createTestDom().root;
const view = createDataView(host, {
  data: [{ id: 1, name: 'Ada' }, { id: 2, name: 'Grace' }, { id: 3, name: 'Linus' }],
  key: 'id',
  template: (item) => `<h4>${item.name}</h4>`,
  itemWidth: 100,
  itemHeight: 60,
  columns: 2,
  gap: 10,
  css: 'person',
  selection: 'multi',
  dragMode: 'both',
  dragCopy: false,
  emptyText: 'No people',
});
view.on('selectionChange', (e) => seen.push(`sel:${e.ids.join(',')}`));

view.data.add({ id: 4, name: 'Margaret' }, 1);
view.data.update(2, { name: 'Grace H.' });
const added = view.data.serialize().map((i) => i.id).join(',');
view.data.sort('name', 'desc');
const sorted = view.data.serialize().map((i) => i.id).join(',');
view.data.filter((item) => item.name.length < 6);
const shown = `${view.data.serialize().length}/${view.data.getLength()}`;
view.data.filter();
view.data.sort();
view.selection.add([1, 3]);
view.selection.remove(1);
const selected = view.selection.getId().join(',');
view.selection.clear();
await Promise.resolve();                                                     // the cards redraw once, after a burst of changes
const cards = [...host.querySelectorAll('.lat-dv-card.person')]
  .sort((a, b) => a.getAttribute('data-index') - b.getAttribute('data-index'))
  .map((c) => c.getAttribute('data-key')).join(',');
const rows = host.querySelector('[role="grid"]').getAttribute('aria-rowcount');
view.destroy();
return [fit, filled, added, sorted, shown, selected, cards, rows, seen.join('|')].join(' || ');

A drag copy's fresh id, and a vetoed beforeDrag

Three drops of the same source item into a target that already holds one: the default generator gives the first two distinct, counted-up ids, and copyId overrides it on the third. Then a card whose press is vetoed by beforeDrag never arms the pointer-move listener a real drag needs — run headless, the drop itself through dropOn (the primitive createDataView and createList share), the veto through a real view.

const { createTestDom, resetTestDom, TestEvent } = await import('../packages/dom/src/renderer/testdom.js');
const { createDataView } = await import('../packages/modules/dataview/index.js');
const { dropOn } = await import('../packages/modules/listview/shared.js');

// dropOn is the primitive both modules' pointer-drag code calls on a cross-view drop.
const target = new Map([['B0', { id: 'B0' }]]);
const zone = {
  owner: { data: { getItem: (id) => target.get(id) } },
  beforeDrop: () => true,
  receive: (item) => target.set(item.id, item),
  afterDrop: () => {},
};
const ids = [];
const dragOf = (overrides) => ({
  source: {}, id: 'A1', item: { id: 'A1', name: 'Ada' }, index: 0, copy: true, key: 'id',
  remove: () => {}, afterDrop: (p) => ids.push(p.ids[0]), ...overrides,
});
dropOn(zone, dragOf());                                           // no collision: A1-copy
dropOn(zone, dragOf());                                           // A1-copy is taken now: A1-copy2
dropOn(zone, dragOf({ copyId: (item) => `custom-${item.name}` })); // the hook wins

resetTestDom();
const host = createTestDom().root;
const win = {
  listeners: new Map(),
  addEventListener(t, fn) { let s = this.listeners.get(t); if (!s) { s = new Set(); this.listeners.set(t, s); } s.add(fn); },
  removeEventListener(t, fn) { const s = this.listeners.get(t); if (s) s.delete(fn); },
};
host.ownerDocument.defaultView = win; // enough for onPointerDown to arm a real drag
const view = createDataView(host, { data: [{ id: 'X0' }], template: (i) => `<div>${i.id}</div>`, dragMode: 'source' });
view.on('beforeDrag', () => false);
const card = host.querySelector('[data-key="X0"]');
card.dispatchEvent(new TestEvent('pointerdown', { clientX: 10, clientY: 10, button: 0 }));
const vetoedListeners = win.listeners.get('pointermove') ? win.listeners.get('pointermove').size : 0;
view.destroy();

return [ids.join(','), vetoedListeners].join(' || ');

DataViewConfig

The configuration for {@link createDataView}: items laid out as cards that wrap into rows, each card drawn by `template`. Cards are `itemWidth` wide and as many as fit go on a row, or `columns` of them share the width.
